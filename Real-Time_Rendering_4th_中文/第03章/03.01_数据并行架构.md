# 3.1 数据并行架构

来源：原书书页 30—33（PDF 物理页 51—54）。

不同的处理器架构采用各种策略来避免停顿。CPU 针对处理种类繁多的数据结构和庞大的代码库进行了优化。CPU 可以包含多个处理器，但每个处理器主要以串行方式运行代码，有限的 SIMD 向量处理只是一个小小的例外。为了尽量减小延迟的影响，CPU 芯片的很大一部分由快速的本地缓存组成，这些存储器中填充着接下来可能需要的数据。CPU 还通过分支预测、指令重排、寄存器重命名和缓存预取等巧妙的技术来避免停顿 [715]。

GPU 采用另一种方法。GPU 芯片的很大一部分面积用于容纳大量处理器，称为**着色器核心**，其数量通常达到数千个。GPU 是一种流处理器，其中由相似数据组成的有序集合会依次得到处理。正因为这些数据具有相似性，例如一组顶点或像素，GPU 才能够以大规模并行的方式处理它们。另一个重要条件是，这些调用要尽可能彼此独立，使它们既不需要相邻调用的信息，也不共享可写的内存位置。有时，为了实现新的有用功能，也会打破这条规则，但这类例外的代价是可能产生延迟，因为一个处理器可能需要等待另一个处理器完成工作。

GPU 针对**吞吐量**进行了优化，吞吐量定义为能够处理数据的最大速率。不过，这种快速处理是有代价的。由于分配给缓存存储器和控制逻辑的芯片面积较少，每个着色器核心遇到的延迟通常明显高于 CPU 处理器遇到的延迟 [462]。

假设一个网格被光栅化后，有两千个像素包含需要处理的片元，那么像素着色器程序就要被调用两千次。设想只有一个着色器处理器，也就是世界上最弱的 GPU。它开始为这两千个片元中的第一个片元执行着色器程序。着色器处理器先对寄存器中的值进行几次算术运算。寄存器位于本地，访问很快，因此不会发生停顿。随后，着色器处理器遇到一条指令，例如纹理访问指令：对于某个给定的表面位置，程序需要知道贴在网格上的图像在该处的像素颜色。纹理是完全独立的资源，不属于像素程序的本地存储器，而且纹理访问可能相当复杂。一次内存读取可能需要数百到数千个时钟周期，在这段时间里，GPU 处理器无事可做。此时，着色器处理器就会停顿，等待纹理的颜色值返回。

为了让这个糟糕的 GPU 变得好得多，可以给每个片元分配一小块存储空间，用于保存它的本地寄存器。这样，着色器处理器在读取纹理时就不必停顿，而是可以切换去执行另一个片元，即两千个片元中的第二个。这种切换极快，除了记下第一个片元当时正在执行哪条指令以外，第一个和第二个片元中的任何内容都不受影响。现在执行第二个片元。与第一个片元一样，先执行几个算术函数，然后又遇到一次纹理读取。着色器核心于是切换到另一个片元，也就是第三个。最终，全部两千个片元都以这种方式得到处理。此时，着色器处理器返回第一个片元。到这时，纹理颜色已经取回并可供使用，因此着色器程序就能继续执行。处理器以同样的方式继续运行，直到遇到另一条已知会导致执行停顿的指令，或者程序执行完毕。与着色器处理器一直专注于单个片元的情况相比，单个片元完成执行所需的时间会更长，但全部片元的总体执行时间却会大幅缩短。

在这种架构中，GPU 通过切换到另一个片元来保持忙碌，从而隐藏延迟。GPU 在这一设计的基础上更进一步，将指令执行逻辑与数据分离。这种安排称为**单指令多数据**（single instruction, multiple data，SIMD），它对固定数量的着色器程序同步执行同一条命令。与为每个程序配备独立的逻辑和分派单元相比，SIMD 的优势在于，用于数据处理和切换的硅芯片资源以及功耗都少得多。用现代 GPU 的术语来表述前面两千个片元的例子，为一个片元进行的每次像素着色器调用都称为一个**线程**。这种线程不同于 CPU 线程。它由一小块用于保存着色器输入值的存储空间，以及着色器执行所需的寄存器空间组成。使用相同着色器程序的线程会被编组成组，NVIDIA 将这些组称为 **warp（线程束）**，AMD 则称之为 **wavefront（波前）**。一个线程束或波前会被调度到一定数量的 GPU 着色器核心上，通过 SIMD 处理来执行，核心数量介于 8 到 64 之间。每个线程映射到一个 **SIMD 通道**。

假设我们有两千个待执行的线程。NVIDIA GPU 上的线程束包含 32 个线程。因此，线程束的数量为 2000 ÷ 32 = 62.5，这意味着需要分配 63 个线程束，其中一个有一半是空的。线程束的执行与前面单个 GPU 处理器的例子相似。着色器程序在全部 32 个处理器上同步执行。遇到内存读取时，所有线程都会同时遇到它，因为所有线程执行的是同一条指令。这次读取表明，该线程束中的线程即将停顿，所有线程都要等待各自不同的结果。此时并不真正停顿，而是换出当前线程束，换入另一个包含 32 个线程的线程束，再由这 32 个核心执行。切换速度与单处理器系统的例子一样快，因为换入或换出线程束时，并不触及各个线程中的数据。每个线程都有自己的寄存器，每个线程束也会记录自己正在执行哪条指令。换入一个新的线程束，只需让这一组核心转而执行另一组线程，没有其他开销。各线程束不断执行或换出，直到全部执行完成。见图 3.1。

**图 3.1**　简化的着色器执行示例。一个三角形的片元在这里称为线程，它们被编入线程束。图中每个线程束画成包含 4 个线程，而实际上包含 32 个线程。要执行的着色器程序共有 5 条指令。由 4 个 GPU 着色器处理器组成的处理器组，为第一个线程束执行这些指令，直到在 `txr` 命令处检测到停顿条件；该命令需要时间来取回数据。随后换入第二个线程束，对它执行着色器程序的前 3 条指令，直到再次检测到停顿。第三个线程束被换入并发生停顿后，再换入第一个线程束，继续执行。如果此时它的 `txr` 命令所需的数据尚未返回，执行才会真正停顿，直到这些数据可用。各个线程束依次完成。

在这个简单例子中，读取纹理所需的内存访问延迟可能导致线程束被换出。实际上，由于切换的代价很低，即使延迟更短，也可能换出线程束。还有其他一些用于优化执行的技术 [945]，但线程束切换是所有 GPU 用来隐藏延迟的主要机制。这一过程的效率受到若干因素影响。例如，如果线程很少，能够创建的线程束也就很少，隐藏延迟就会变得困难。

着色器程序的结构是影响效率的一项重要特征。其中一个主要因素是每个线程使用的寄存器数量。在前面的例子中，我们假定两千个线程能够同时驻留在 GPU 上。每个线程所关联的着色器程序需要的寄存器越多，能够驻留在 GPU 中的线程就越少，因而线程束也越少。线程束不足可能意味着无法通过切换来缓解停顿。驻留的线程束称为处于“在途”（in flight）状态，这个数量称为**占用率**（occupancy）。高占用率意味着有许多线程束可供处理，因此处理器空闲的可能性较小。低占用率往往会导致较差的性能。内存读取的频率也会影响需要隐藏多少延迟。Lauritzen [993] 概述了着色器使用的寄存器数量和共享内存如何影响占用率。Wronski [1911, 1914] 讨论了理想占用率会如何随着色器所执行的操作类型而变化。

另一个影响整体效率的因素是由 `if` 语句和循环引起的**动态分支**。假设着色器程序遇到一个 `if` 语句。如果所有线程求值后都进入同一个分支，线程束就可以继续执行，不必考虑另一个分支。但如果部分线程，哪怕只有一个线程，选择了另一条路径，那么线程束就必须执行两个分支，并丢弃各个线程不需要的结果 [530, 945]。这一问题称为**线程分歧**：少数线程可能需要执行一次循环迭代，或执行一条 `if` 路径，而线程束中的其他线程不需要这样做，导致其他线程在这段时间里空闲。

所有 GPU 都实现了这些架构思想，形成了具有严格限制、但每瓦功耗能提供巨大计算能力的系统。作为程序员，理解这一系统如何运作，将帮助你更高效地利用它提供的算力。在接下来的各节中，我们将讨论 GPU 如何实现渲染流水线、可编程着色器如何工作，以及 GPU 各个阶段的演变和功能。
