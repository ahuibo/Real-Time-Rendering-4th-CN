# 第3章 图形处理单元

> 来源：Real-Time Rendering, Fourth Edition，书页 29—30（PDF 第50—51页）。

> “显示器就是计算机。”
>
> ——黄仁勋（Jen-Hsun Huang）

从历史上看，图形加速最初是对与三角形重叠的每条像素扫描线上的颜色进行插值，然后显示这些值。加入访问图像数据的能力后，就能够把纹理应用到表面上。再加入用于对 ![数学符号](../assets/math/eq_03_00_00efa9f788eb2b.png) 深度进行插值和测试的硬件，就能提供内置的可见性检查。由于这些处理过程使用频繁，人们将其交由专用硬件执行，以提高性能。在随后各代硬件中，渲染流水线的更多部分被加入进来，各部分的功能也大幅增加。专用图形硬件相对于 CPU 唯一的计算优势是速度，但速度至关重要。

在过去二十年中，图形硬件经历了令人难以置信的变化。首款包含硬件顶点处理功能的消费级图形芯片——NVIDIA 的 GeForce 256——于 1999 年出货。NVIDIA 创造了“图形处理单元”（graphics processing unit，GPU）这一术语，用来区分 GeForce 256 与此前只能进行光栅化的芯片，而这个名称也沿用下来。在接下来的几年里，GPU 从复杂固定功能流水线的可配置实现，演变成高度可编程的平台，开发者可以在上面实现自己的算法。各种可编程着色器成为控制 GPU 的主要手段。为提高效率，流水线的某些部分仍然只能配置、不能编程，但总体趋势是走向可编程性与灵活性 [175]。

GPU 通过专注于一组范围较窄、能够高度并行化的任务，获得了极高的速度。例如，它们具有专门实现 ![数学符号](../assets/math/eq_03_00_00efa9f788eb2b.png) 缓冲、快速访问纹理图像和其他缓冲区，以及确定哪些像素被三角形覆盖的定制电路。这些部件如何完成各自功能，将在第 23 章介绍。在一开始，更重要的是了解 GPU 如何让其可编程着色器实现并行。

第 3.3 节解释着色器如何工作。目前，你需要知道的是：着色器核心是一个小型处理器，用来完成某种相对独立的任务，例如把顶点从世界中的位置变换为屏幕坐标，或者计算被三角形覆盖的像素的颜色。由于每帧都有成千上万乃至数百万个三角形被送往屏幕，每秒可能发生数十亿次着色器调用，也就是数十亿个分别运行着色器程序的实例。

首先，延迟是所有处理器都面临的问题。访问数据需要一定时间。理解延迟的一种基本方式是：信息离处理器越远，等待就越久。第 23.3 节将更详细地讨论延迟。访问存储在内存芯片中的信息，比访问本地寄存器中的信息耗时更长。第 18.4.1 节会更深入地讨论内存访问。关键在于，等待数据取回意味着处理器处于停顿状态，从而降低性能。
