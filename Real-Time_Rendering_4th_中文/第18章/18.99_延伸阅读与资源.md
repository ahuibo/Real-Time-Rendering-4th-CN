# 第18章 延伸阅读与资源

来源：原书书页 814—815（PDF 第 835—836 页），“Further Reading and Resources”及其全部后续文字；PDF 第 837 页仅有出版商标志及网址，记录于文末，下一章从 PDF 第 838 页开始。原文标题未编号，此处文件名中的 18.99 仅用于合并排序。

移动设备在各项工作耗时的分配上，可能有不同的平衡，尤其是在使用基于分块的架构时。Merry [1200] 讨论了这些成本，以及如何有效使用这类 GPU。Pranckevičius 和 Zioma [1433] 的报告深入介绍了移动设备优化的许多方面。McCaffrey [1156] 比较了移动与桌面架构及其性能特征。像素着色通常是移动 GPU 上最大的开销。Sathe [1545] 和 Etuaho [443] 讨论了移动设备上的着色器精度问题和优化。

对于桌面平台，Wiesendanger [1882] 全面介绍了现代游戏引擎的架构。O’Donnell [1313] 展示了基于图的渲染系统的优点。Zink 等人 [1971] 深入讨论了 DirectX 11。De Smedt [331] 针对电子游戏中常见的性能热点提供了指导，其中包括 DirectX 11 和 12、多 GPU 配置以及虚拟现实的优化。Coombes [291] 概述了 DirectX 12 的最佳实践，Kubisch [946] 则提供了关于何时应使用 Vulkan 的指南。关于从旧式 API 移植到 DirectX 12 和 Vulkan，已经有大量报告 [249, 536, 699, 1438]。当你读到这里时，无疑还会有更多。可以查看 NVIDIA、AMD 和 Intel 等独立硬件供应商（IHV）的开发者网站、Khronos Group 的网站、互联网上的其他资源，以及本书网站。

虽然年代稍早，Cebenoyan 的文章 [240] 仍然具有参考价值。它概述了如何查找瓶颈，以及提高效率的技术。Fog [476] 和 Isensee [801] 的 C++ 优化指南颇受欢迎，可以在网上免费获取。Hughes 等人 [783] 以现代视角深入讨论了如何使用跟踪工具和 GPUView，分析瓶颈发生的位置。虽然重点是虚拟现实系统，但其中讨论的技术适用于任何基于 Windows 的机器。

Sutter [1725] 讨论了 CPU 时钟频率如何趋于平缓，以及多处理器芯片组如何兴起。关于发生这一变化的更多原因，以及芯片如何设计的信息，可参阅 Asanovic 等人 [75] 的深入报告。Foley [478] 在图形应用程序开发的背景下，讨论了多种形式的并行性。《Game Engine Gems 2》[1024] 收录了数篇介绍如何为游戏引擎编写多线程部分的文章。Preshing [1445] 解释了 Ubisoft 如何使用多线程，并具体说明如何使用 C++11 的线程支持。Tatarchuk [1749, 1750] 的两场报告详细介绍了游戏《Destiny》使用的多线程架构和着色流水线。
