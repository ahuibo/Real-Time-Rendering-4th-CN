# 18.1 性能分析与调试工具

来源：原书书页 784—785（PDF 第 805—806 页）。本节自 18.1 标题起，至 18.2 标题前止；已核对 PDF 第 807 页的节边界。

性能分析与调试工具对于找出代码中的性能问题可能具有极高的价值。不同工具的能力各不相同，可能包括：

- 帧捕获与可视化。通常可以逐步回放一帧，同时显示正在使用的状态和资源。
- 分析 CPU 和 GPU 各部分的耗时，包括调用图形 API 所花费的时间。
- 调试着色器，并且可能支持热编辑，以便查看修改代码后的效果。
- 使用应用程序中设置的调试标记，帮助识别代码的不同区域。

性能分析与调试工具会因操作系统、图形 API 而异，而且往往也因 GPU 厂商而异。大多数搭配都有相应的工具，这也就是诸神创造 Google 的原因。不过，为了让你开始探索，我们还是会具体提到几个面向交互式图形的工具包：

- **RenderDoc** 是 Windows 上的一款高质量调试器，支持 DirectX、OpenGL 和 Vulkan，最初由 Crytek 开发，如今已经开源。
- **GPU PerfStudio** 是 AMD 为其图形硬件产品提供的工具套件，可以在 Windows 和 Linux 上运行。其中一个值得关注的工具是静态着色器分析器，无须运行应用程序就能给出性能估计。AMD 的 Radeon GPU Profiler 则是一个独立但相关的工具。
- **NVIDIA Nsight** 是一个具有广泛功能的性能分析与调试系统。它在 Windows 上与 Visual Studio 集成，在 Mac OS 和 Linux 上与 Eclipse 集成。
- 微软的 **PIX** 长期以来一直为 Xbox 开发者所使用，如今又重新面向 Windows 上的 DirectX 12 推出。对于较早版本的 DirectX，可以使用 Visual Studio 的 **Graphics Diagnostics**。
- 微软的 **GPUView** 使用 Windows 事件跟踪（Event Tracing for Windows，ETW），这是一种高效的事件记录系统。GPUView 是使用 ETW 会话数据的多个程序之一。它着重分析 CPU 与 GPU 之间的交互，显示哪一方是瓶颈 [783]。
- **Graphics Performance Analyzers**（GPA，图形性能分析器）是英特尔提供的一套工具，并不局限于英特尔的图形芯片，主要用于性能分析和帧分析。
- OSX 上的 Xcode 提供了 **Instruments**，其中包含多种工具，用于计时、性能、网络、内存泄漏等方面。值得一提的有 **OpenGL ES Analysis**，它能够检测性能问题和正确性问题，并提出解决办法；还有 **Metal System Trace**，它提供来自应用程序、驱动程序和 GPU 的跟踪信息。

这些是已经存在了几年的主要工具。不过，有时没有任何工具能够胜任所需的工作。大多数 API 都内置了计时器查询调用，用来帮助分析 GPU 的性能。一些厂商还提供了程序库，用于访问 GPU 计数器和线程跟踪信息。
